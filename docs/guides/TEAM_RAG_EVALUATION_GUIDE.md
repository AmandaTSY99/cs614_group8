# Comparative Engineering & Evaluation Guide: 4 Financial RAG Systems

**Scope:** Standardized evaluation protocol across System A, System B, System C v1, and System C v3.  
**Branch:** `dev`  
**Purpose:** Instructions for connecting to the 4 RAG systems and executing standardized evaluations for **RQ1 (Retrieval Completeness)**, **RQ2 (Grounding & Citations)**, and **RQ3 (Inference Economics)**.

---

## 1. What are the 4 Systems We Are Testing?

Every research question in our paper evaluates the exact same **4 RAG systems**:

1. **`system_a` (Vanilla Dense Baseline):** Standard vector search (top-10 chunks from Supabase) $\rightarrow$ 1 LLM answer.
2. **`system_b` (Advanced Hybrid Single-Pass):** Vector search + BM25 keyword search + cross-encoder reranking $\rightarrow$ 1 LLM answer. Does **not** hop.
3. **`system_c_v1` (Adaptive Multi-Hop):** Breaks question into sub-queries, loops through 1 to 3 retrieval hops, checks evidence with a Critic, and verifies numbers with a Guardrail.
4. **`system_c_v3` (Agentic Multi-Hop with Schema-Aware Sufficiency & Financial Tools):** Pulls structured financial data from an SEC XBRL tool first, then loops through 1 to 3 hops with Critic, structural table continuity stitching, and Guardrail.

## 3. How to Query the Systems (Simple Python Code)

All 4 systems are connected to a single function in `scripts/rq2/adapters.py`. Here is how any script can query them:

```python
import os
from dotenv import load_dotenv
load_dotenv(override=True)

from scripts.rq2.adapters import get_adapters

# Load the 4 systems
adapters = get_adapters(["system_a", "system_b", "system_c_v1", "system_c_v3"])

# Example question
question = {
    "id": "q-001",
    "question": "What was Apple's total revenue in fiscal year 2021?",
    "ticker": "AAPL",
    "target_tickers": ["AAPL"],
    "year": 2021,
    "fiscal_years": [2021]
}

# Run any system
output = adapters["system_c_v3"].answer(question)

print("Answer:", output["answer"])
print("Retrieved Chunks:", len(output["retrieved_contexts"]))
print("Latency:", output["latency_ms"], "ms")
```

### What `output` Contains:
* `output["answer"]`: The final text generated by the model.
* `output["retrieved_contexts"]`: List of raw text chunks fetched from SEC filings.
* `output["contexts_meta"]`: List of chunk metadata (`chunk_id`, `ticker`, `fiscal_year`, `section`).
* `output["citations"]`: List of citations linked to chunks.
* `output["guardrail_report"]`: Hallucination audit report (System C only).
* `output["hops"]`: Number of retrieval hops taken (1 for System A/B; 1 to 3 for System C).
* `output["latency_ms"]`: Wall-clock execution time in milliseconds.
* `output["tokens"]`: `{"prompt": ..., "completion": ..., "total": ...}` token counts.

All execution commands use Docker, mounting your local workspace so all outputs (`reports/`) persist directly to your machine.

> [!NOTE]
> `runner` (or `system-c`) in the Docker command is simply the name of the Docker execution container. Running `scripts/rq1/evaluate_rq1.py` evaluates **all 4 systems** (`system_a`, `system_b`, `system_c_v1`, `system_c_v3`) side-by-side, not just System C!

### Research Question 1 (RQ1): Retrieval Completeness & Cross-Section Discovery
* **Objective:** Determine whether adaptive multi-hop retrieval uncovers scattered evidence across non-adjacent 10-K sections (e.g., Item 7 MD&A and Item 8 Footnotes) that single-pass architectures omit.
* **Evaluation Pipeline:** Executed via `scripts/rq1/evaluate_rq1.py` against all 4 systems and Supabase `retrieved_contexts`:
  ```bash
  # Instant evaluation across ALL 4 SYSTEMS against pre-computed benchmark records (0 API cost, takes ~2s):
  docker compose run --rm runner python scripts/rq1/evaluate_rq1.py
  ```
  *(Note: `runner` or `system-c` can be used interchangeably as the container name).*

### RQ1 Evidence Metrics vs RQ2 Citation Metrics
The names are similar, but they measure different pipeline stages and are not interchangeable.

| | RQ1 `recall@all` / `average_precision` | RQ2 `citation_recall` / `citation_precision` |
|---|---|---|
| **What's checked** | Everything the system retrieved, whether or not the answer used it | Only the chunks the answer cites in its citation tags |
| **Pipeline step** | Retrieval: did the system find the evidence? | Generation: did the answer point to the right sources? |
| **What counts as a match** | The specific gold evidence quotes from the golden set | The 10-K section (e.g. Item 7, Item 8) the gold answer comes from |
| **How a match is decided** | Text overlap: a 6-word phrase or at least 65% of the quote's words appear in the chunk (`scripts/rq1/matching.py`) | Section labels: the cited chunk's Item number equals a target section's (`scripts/rq2/metrics_custom.py`) |
| **Recall** | Share of gold quotes found anywhere in the retrieved chunks | Share of target sections the answer cites at least once |
| **Precision** | Rank-aware: RAGAS-style average precision, rewarding relevant chunks ranked near the top | Not rank-aware: share of the cited sections that are target sections |
| **Answers with no citations** | Not applicable (scores the retrieved chunks, not citations) | Scored N/A, not 0. Tracked separately by `citation_coverage` |

* **Example:** if the gold evidence is one sentence in Item 7, RQ1 recall is 1 only if that sentence (or most of its words) was retrieved. RQ2 citation recall is 1 if the answer cites *any* Item 7 chunk, even one about something else.
* **Neither is LLM-judged.** RQ1's `recall@all` / `average_precision` (previously named `context_recall` / `context_precision`) use RAGAS-style formulas with lexical relevance labels; they are not RAGAS scores. The LLM-judged versions (`scripts/rq1/score_ragas.py`, `scripts/rq2/score.py`) have only been run on the 3-question RQ2 smoke test (`reports/rq2/smoke/report_scores_gpt4omini.md`).
* **Always report citation precision/recall next to `citation_coverage`.** Answers without citations drop out of the average, so a system that often omits citations can look better than it is. For example, System B's citation recall is 0.97 over the 67 of 97 answers that cite; counting no-citation answers as 0 gives 0.67, the lowest of the four systems.

## 7. Strict Academic Rigor Rules (For AI Coding Agents)

When your AI assistants (Claude, Cursor, Copilot) write or modify evaluation code, they must strictly follow these 4 rules:

1. **Firewall Integrity:** Do not leak ground-truth answers or evidence into the prompt. The RAG systems must answer blind.
2. **Benchmark Uniformity:** Only evaluate against `data/benchmark_qa_pool_2015.json` (97 questions). Never swap in a synthetic or unapproved test set.
3. **No UI Edits:** `app.py` is locked for the Streamlit demo. All evaluation work must remain strictly in `scripts/` and CLI.
4. **Fail-Fast / Loud Stops:** Do not write silent `try...except: pass` blocks that hide failures. If a query fails, dump the stack trace and fail loudly so data is never silently corrupted.
