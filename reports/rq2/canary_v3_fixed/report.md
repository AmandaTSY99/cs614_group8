## Notes

- Context Precision is order-sensitive: it rewards relevant contexts ranked early. `retrieved_contexts` are kept in the order each system produced them (System C: retrieval order across hops, with v2's XBRL blocks first).
- Citation precision/recall/F1 are section-level (top-level 10-K item, `financials.csv` = any `[F-…]` citation), because the golden set has no gold chunk IDs. Answers with no citations are N/A, not 0; `citation_coverage` is the share of answers with at least one citation.
- Section aliases (a limitation of section-level matching): a cited `Item 15` chunk that is financial statements or notes counts as `Item 8`, and a cover-page chunk (no Item heading; registrant name, address, file number) counts as `Item 1`, matching how the golden set labels those facts.
- RAGAS metrics see the answer with citation tags stripped.
- Refusals ("Not found in the provided context", "cannot be determined", ...) are counted by `abstained`. They are N/A for faithfulness (no claims to check) and score 0 for factual correctness, instead of the 1.0 RAGAS would give a claim-free answer.
- RAGAS references come from the benchmark: factual correctness uses the gold answer plus its key points; context recall / precision use the gold evidence quotes plus the gold answer, because a computed answer such as "-30.36%" does not appear in any filing. A bare negative gold number is also written as a decrease.
- Numeric accuracy accepts the unsigned value of a negative gold number ("-25.64%" matches "decreased by 25.6%", 0.5% relative tolerance), so a wrong sign is not caught.
- Categories: multi_company_comparison is only questions across companies; one company across years is cross_section_multihop. `dim=value` sections use the proposal's attributes from the benchmark: answer_type (type), evidence_format (recipe), hop, task (calculation when the gold has a program), evidence_scope (scope).
